# Agent Note: Pwsh 引导在初始就绪后开始

Status: implemented

[English](2026-09-02-pwsh-bootstrap-readiness.md) | 中文

## 问题

持久 pwsh 后端过去会在 PTY 提供方初始化后立即写入提示符函数与 UTF-8 前导。在负载较高的 Windows 主机上，PSReadLine 此时可能仍在绘制原始提示符，并消费该输入或让输入与提示符交错。随后，启动循环既观察不到已安装的 `dsh> ` 提示符，也得不到权威的 stdin-read 证据，最终会在启动超时处拒绝一个原本健康的 shell。

## 决策

Pwsh 启动先执行一次不提交内容的空发送，并等待其结算。之后后端才提交编码前导与提示符函数。现有设置循环继续要求写入后的 `stdin_read` 证据包含完全匹配的已安装提示符标记；调用方的取消信号与同一条绝对启动 deadline 覆盖两个阶段。

Bash 的启动保持不变，因为其私有提示符会在 shell 启动前通过进程环境安装。

## 曾考虑的替代方案

**增加启动超时。** 不予采用，因为该故障是输入顺序竞态；更长的等待无法恢复已经被 PSReadLine 消费或交错处理的设置文本。

**重试引导输入。** 不予采用，因为在部分写入结果不确定时重放 shell 设置可能重复执行命令。就绪结算会改为建立一个安全且唯一的写入时点。

## 验证

terminal-bash 单元测试断言初始就绪发送、后续引导发送、提示符标记的后续轮询，以及取消信号在两次发送中的传递。真实 pwsh 集成测试仍是平台所属的证明，确认 Windows shell 会在启动完成前到达 `dsh> `。

## 后果

Pwsh 启动会在写入设置输入前多执行一次就绪结算。这样可以移除与原始提示符的竞态，同时不削弱已安装提示符要求，也不延长配置的启动 deadline。
