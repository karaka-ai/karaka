# Agent Note：Windows 覆盖率测试的确定性断言与释放预算

Status: implemented

[English](2026-08-31-windows-coverage-flaky-test-budgets.md) | 中文

## 问题

运行器资源争用时，真实子进程可能需要更长时间才报告退出。使用 100–300 毫秒确认预算的 SDK 释放测试可能将缓慢回收判为失败，即使释放流程已成功终止子进程。这些测试验证信号升级和清理，而不是性能上限。

投影缓存写入也会异步完成。断言必须观察能证明完成的持久化记录或警告。Karaka 已经轮询这些结果，并在所属上下文释放前捕获创建的 Session；这些检查保持不变。

## 决策

真实 SDK 初始化和释放流程测试使用产品的 3,000 毫秒信号宽限期。并发 SDK 子代理诊断测试使用导出的关闭、EOF 宽限期和信号宽限期默认值。SDK 测试仍明确指定初始化截止时间及用于触发目标释放路径的较短 EOF 窗口。

修改后的 SDK 释放测试夹具在初始化前注册清理。并发诊断夹具即使遇到断言失败或另一个启动失败，也会等待每个已获取运行完成释放。两个运行仍并发启动，各自的诊断类别断言保持独立。

确定性的模拟子进程测试保留 10 毫秒失败预算。永不退出的子进程仍必须使释放拒绝；延长真实进程的确认预算不会将该失败变成成功。运行时超时、持久化行为和 CI 覆盖率要求均不变。

## 验证

所属测试套件覆盖投影缓存记录和警告、真实 SDK 进程释放、确定性的卡住子进程失败，以及并发子代理诊断。独立测试进程会并发使用各自拥有的资源。原生 Windows 时序由其 CI 通道负责；本地 POSIX 结果不能证明 Windows 通过。

## 已考虑的替代方案

**保留真实进程的较短确认预算。** 这会引入与被测行为无关的回收延迟限制。产品默认值为操作系统报告退出留出时间，同时保留有限的失败截止时间。

**用休眠替换持久化断言，或重试失败测试。** 两者都不能证明等待的状态。缓存轮询保留精确的记录和警告断言；SDK 测试保留信号升级和诊断断言。

## 结果

真实进程测试使用部署默认值确认退出。确定性测试仍在指定预算内拒绝卡住的子进程，夹具清理则在断言失败时等待完全停止。Karaka 现有的缓存轮询和 Session 释放覆盖保持完整。
