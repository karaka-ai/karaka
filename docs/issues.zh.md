# 未解决问题

[English](issues.md) | 中文

这是 Karaka 在实现或审查过程中发现的具体未解决缺陷和架构缺口的权威清单，不是功能路线图。应保留稳定 ID，记录问题的发现位置，并明确它是否阻塞暴露该问题的变更。

如果问题可以在当前拉取请求引入的包或 API 内修正，则属于当前拉取请求。如果正确修复需要改变已有的跨包契约或执行保证，则属于架构待办。

## PR #80 暴露的跨接缝待办

这些确实是 Karaka 的问题，但仅修改提供方无法安全解决：

| ID | 状态 | 负责人 | 问题 | 所需设计 |
| --- | --- | --- | --- | --- |
| KARAKA-004 | 已推迟 | 智能体运行时 + 权益 | 上游调用在取消、失败或不完整时仍可能计费，但当前支出只随成功的 `ModelGeneration` 传递，因此不会记录。 | 支持重试与未知结果语义的幂等预留和结算。 |
| KARAKA-005 | 已推迟 | 智能体运行时 + 存储 | 提供方中立的消息和会话契约只保存角色与文本，因此推理项、阶段和工具输出等提供方原生重放状态无法跨持久多轮聊天保留。 | 带版本和重放规则的提供方中立持久轮次状态契约。 |
| KARAKA-006 | 已推迟 | 配置基础层 | 提供方凭证只是普通 schema 字符串。环境变量回退可以避免把密钥写入 YAML，但 Loader 和 schema 工具没有共享的密钥与脱敏契约。 | 所有提供方都可使用的密钥感知配置与诊断脱敏约定。 |

## 维护规则

只有在失败模式和归属边界都明确时才新增问题。解决问题时，应在拉取请求中引用其 ID，并在同一变更中将其从此未解决清单移除。
