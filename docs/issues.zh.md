# 未解决问题

[English](issues.md) | 中文

这是 Karaka 在实现或审查过程中发现的具体未解决缺陷和架构缺口的权威清单，不是功能路线图。应保留稳定 ID，记录问题的发现位置，并明确它是否阻塞暴露该问题的变更。

如果问题可以在当前拉取请求引入的包或 API 内修正，则属于当前拉取请求。如果正确修复需要改变已有的跨包契约或执行保证，则属于架构待办。

## PR #80：OpenAI 模型提供方

以下问题由 PR #80 负责；在解决之前，不应把它描述为生产就绪：

| ID | 状态 | 问题 | 完成条件 |
| --- | --- | --- | --- |
| KARAKA-001 | 未解决 | 流式提供方忽略 OpenAI 明确的 `response.error`、`response.failed` 和 `response.incomplete` 事件，导致有用的诊断信息丢失。 | 转换并测试这些终止事件，且不得把它们报告为成功生成。 |
| KARAKA-002 | 未解决 | 固定配置的 token 费率被描述为精确的提供方支出，但服务层级、条件定价和逐调用整数舍入都可能与账单不同。 | 定义并强制执行受支持的定价假设，在需要时传递显式层级；除非能保证与账单一致，否则应将结果描述为配置计量。 |
| KARAKA-003 | 未解决 | 提供方和包的加固尚未完成：缺少设置 YAML 挂载冒烟测试，重要的异常用量与舍入边界没有测试，新 LICENSE 年份也与仓库不一致。 | 增加针对性测试并修正包元数据。 |

## PR #80 暴露的跨接缝待办

这些确实是 Karaka 的问题，但仅修改提供方无法安全解决：

| ID | 状态 | 负责人 | 问题 | 所需设计 |
| --- | --- | --- | --- | --- |
| KARAKA-004 | 已推迟 | 智能体运行时 + 权益 | 上游调用在取消、失败或不完整时仍可能计费，但当前支出只随成功的 `ModelGeneration` 传递，因此不会记录。 | 支持重试与未知结果语义的幂等预留和结算。 |

## 维护规则

只有在失败模式和归属边界都明确时才新增问题。解决问题时，应在拉取请求中引用其 ID，并在同一变更中将其从此未解决清单移除。
