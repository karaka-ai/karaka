# 未解决问题

[English](issues.md) | 中文

这是 Karaka 在实现或审查过程中发现的具体未解决缺陷和架构缺口的权威清单，不是功能路线图。应保留稳定 ID，记录问题的发现位置，并明确它是否阻塞暴露该问题的变更。

如果问题可以在当前拉取请求引入的包或 API 内修正，则属于当前拉取请求。如果正确修复需要改变已有的跨包契约或执行保证，则属于架构待办。

## 维护规则

只有在失败模式和归属边界都明确时才新增问题。解决问题时，应在拉取请求中引用其 ID，并在同一变更中将其从此未解决清单移除。
